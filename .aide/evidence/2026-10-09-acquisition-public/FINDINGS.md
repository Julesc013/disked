# Public acquisition findings

The build generator initially rejected the new 17-command profile because its
explicit handler allowlist and three-component selection still described dev.20.
The guard remains: the supported set, exact acquisition provider and four-part
selection now match the implemented development contract. Raw failure retained.

The first public fixture incorrectly expected exact resubmission to be refused.
The existing DE-103 worker contract instead requires observation without another
attempt. The corrected test proves the same operation identity and byte-for-byte
unchanged store, rather than merely accepting exit zero. No runtime replay policy
was changed to satisfy the fixture.

The fixture next expected invalid internal worker-role arguments to use the
public refusal exit. Source inspection established the separate capability role's
existing 199 outcome. The normative prototype now states that distinction; the
test additionally requires no output and unchanged fixture files. Public command
exit semantics remain unchanged. This does not assert system-wide absence of
all effects; observed fixture scope is explicit.

The full regression run then exposed a duplicate frontend keyword in the older
form harness, because the extended console helper now reports that field itself.
The corrected wrapper verifies it is TUI and retains the helper's field once.
The raw failing full-suite log, corrected working run and clean reproduction are
retained. Assertions and actual native journeys remain intact.

The complete build-identity expectation also needed the newly specified exact
acquisition provider field. It still compares the complete object, rather than
ignoring additions. An input-closure check exposed that a catalogue prose change
after the first build had made that build identity stale. A frozen full rebuild
and regression run then verified every input hash; neither check was weakened.

A second full run caught a timing assumption in the cancellation fixture. The
worker validly paused before its first checkpoint; the fixture had asserted a
nonzero checkpoint without first observing one. The corrected fixture waits for
a real partial checkpoint before cancellation, then retains the same nonzero,
partial-copy, original-capture and resumed-byte assertions. The failing full run
and three affected-group reruns are retained alongside clean full reproduction.
No cancellation or resume implementation changed to satisfy this test.

The full-watch fixture deliberately expands completed history after observing
owned worker exit, then rebinds record indices/digests. It is labelled synthetic
in the source and results. Actual worker effects and cancellation/resume are
verified separately; these generated chains are not authentic provenance.

Visual inspection found one execute-review screenshot contained a black client
area despite a title bar; the existing capture heuristic counts whole-window
colours and can accept a frame alone. That raw capture remains. A supplemental
owned-window redraw capture verifies more than ten client colours, less than
90% black client area, the exact reviewed parameters, null graph revision and
no submitted copy/output effects. It was manually inspected. The reusable
capture script and its result/log are retained; strengthening the shared
screenshot helper remains a harness issue. This is not proof of an intermittent
product rendering defect or of qualification on other desktops/hosts.

The supplemental wrapper initially duplicated the phase from the preparation
result before any GUI/effects. Its retained failure was repaired by selecting
only the definition and digest for the exact execute parameters.

W033's remaining requirement/fixture audit and the wider platform/storage
programme stay open. No owner acceptance, independent safety qualification,
physical access, release, signing or publication was manufactured.
