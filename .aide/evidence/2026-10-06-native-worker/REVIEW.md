# DE-W016 local agent review

The bounded fake-worker implementation is suitable for local continuation after
its retained native checks and clean reproduction. This is an agent code/evidence
review, not owner acceptance, independent security qualification or permission
for real storage, elevation or release.

The command boundary selects four compiled fixtures and an explicit disposable
directory. No received plan, provider library or target path is executed by the
worker. Shared CLI/stdio/GUI/TUI dispatch uses the same handler. The only simulated
effect is an in-memory counter; evidence files have a separate declared write
effect. Discovery leaves broader commands planned.

Reviewed boundaries:

- Admission first claims an immutable request identity. Same-definition repeats
  inspect it; conflicting or unreadable claims cannot spawn replacement work.
- The resolved same executable receives four restricted inherited capabilities.
  A test-owned extra inherited client handle is excluded from the worker.
  Explicit invalid standard handles avoid Windows supplying default character
  channels when startup handles are null. The worker checks usable channels,
  capability kinds/file identities, compiled identities and actual job limits.
- The process job has one active slot, a 128 MiB process-memory limit and no
  kill-on-client-close policy. A test-only delayed executable exercises the
  admission timeout without terminating or restarting its eventual worker.
- An append-only, flushed record sequence separates operation/attempt/effect,
  cancellation and recovery state. Its reader independently replays guarded
  transitions and verifies hashes; malformed tails and late epochs cannot become
  successful completion. Python producer validation independently checks integer
  bounds, field relationships and record digests.
- Cancellation before effect dispatch requires a checkpoint acknowledgement.
  Cancellation after dispatch cannot erase an effect or imply quiescence.
  Verification failure remains distinguishable from lost worker observation.
- Human and graphical result notices retain accepted/unknown states and operation
  identity instead of treating every nonzero exit as a generic failed request.

Corrections made during implementation include the null-standard-handle startup
failure, old syntax fixtures for now-defined operation operands, an incorrect test
flag spelling, and unreadable existing admission claims. Regression fixtures use
the owning command contract rather than preserving those obsolete assumptions.

Remaining limits are explicit. This is a private development encoding, not the
production journal or public asynchronous ABI. File I/O can block; broader hang,
exhaustion and event-stream containment belongs to DE-W017. One job bounds one
operation, not a global aggregate of user-created operations. Directory/image
locks, local SID/computer binding and DACLs do not establish a sandbox, trusted
loader or same-user tamper protection. The tested host injects Windhawk modules.
There is no real storage, privilege, power-loss recovery or other-platform
qualification. Owner acceptance remains pending.
