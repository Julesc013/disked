# Implementation findings and retained corrections

The bounded assignment connected action-time fake model proofs to private binary
journal declarations. Source checkpoint 028d3c3c3ea20846e07e880b29c0bef9cce8ca2e
follows base 63554a279a57017d4786f398042b136e15debee8. It adds a native history
projection, not a live binary append/flush adapter or a product writer.

Integration exposed differences in observable ordering. The model previously
allowed seal with a pre-exit capture and cancellation acknowledgement for an
undispatched but intended step without before-state reconciliation. Those paths
now require the actual missing captures/reconciliation. New regression cases
retain the rejected old paths; updated healthy fixtures supply the required actions.
Capture claims also advance across intention, completion, recovery, checkpoint and
seal. New attempts cannot recycle a recovery capture as checkpoint evidence.

The previous semantic reader compared every declared exit with its latest capture.
After an already exited worker was reconciled, that made later seals require a
new exit epoch for a worker that had not restarted. The reader now retains the
first exit epoch for an attempt; later recovery/seal claims must match it until
checkpoint admission. Fresh captures still advance. The first semantic run retained
four fixture failures: two seals and two event-budget fixtures supplied renewed
exit epochs. Their builders now retain the original exit, and two explicit
contradictory-exit regression cases reject redefinition. Budget expectations remain
unchanged; no native validation was relaxed to accept a contradictory exit.

The first grouped journal run failed the guarded suite's input-shape assertion
because a new checkpoint regression fixture omitted its required fault field.
Adding fault=none restored the intended stale-capture probe. Logs of both failures
and subsequent successful runs remain here. Preliminary working-tree runs are
exploratory evidence; the clean source-bound reproduction is the qualifying result.

A review found stable_bytes initially included the generated header when no records
were acknowledged. It now returns zero for zero stable entries. The header is a
fixture supplied for inspection, not observed persisted storage. Positive extents
map retained stable record counts into encoded coordinates; they confer no real
durability. Native binary tail cuts encode the retained attempted candidate and
keep half its bytes. They do not pretend torn JSON bytes are actual binary bytes.

Actual native model histories are independently encoded and hashed in Python.
Copied generation prefixes retain exact binary bytes and recovery references.
Shape/chain/budget failures reject projection; a self-consistent contradictory
resource declaration remains in generated bytes and the semantic reader rejects
it without repair, retaining its accepted bootstrap prefix. All authority and
physical durability claims remain false.
