# Source ownership and file map

This contributor map explains the current implementation. [DE-011](../spec/architecture/repository.md) owns repository/naming policy; [DE-010](../spec/architecture/system.md) owns dependency rules. This guide does not create another command registry or admit a platform/provider. It includes private prototypes, so a file's existence is not a claim of product availability.

CLI has its own `source/apps/disked/cli/` folder. CLI formats a single invocation's output; the interactive shell owns an ongoing editable session; TUI owns text navigation; GUI owns graphical interaction. `app.*` is the composition host that selects these frontends and wires providers. Calling that host `cli.*` obscured its wider responsibility.

The GUI and TUI models use the short, explicit `gui_model.*` and `tui_model.*` names, matching `shell_model.*`. The GUI model sits directly in `gui/` because it contains no Win32 calls. Actual Win32 window code belongs in `platform/windows/ui/`. Console input, terminal modes, handle ownership and restoration belong in `platform/windows/console/`; they serve TUI and shell without owning either interface's semantic state.

```text
source/
  portable/       bounded algorithms over supplied bytes; no host I/O
  runtime/        shared meaning, contracts, state and safety rules
  providers/      concrete storage/image/evidence backends
  platform/       host APIs, processes, handles, console and windows
  apps/disked/    product composition and frontend interaction
    app.*
    cli/cli.*
    tui/tui_model.*
    shell/shell_model.*
    gui/gui_model.*
```

Choose an owner by responsibility, not by whichever caller first needs it. A parser belongs in `portable/`; the meaning of an observation belongs in `runtime/`; collecting concrete storage facts belongs in `providers/`; the host API and process lifetime belong in `platform/`; selecting implementations belongs in `apps/disked/`. Two files can use the same OS without having the same responsibility. Conversely, a Windows API wrapper and a Windows storage provider have different owners even though both are Windows-specific.

Platform entry/UI/console hosts consume this product's frontend factories/models. They are concrete application hosts, not a platform-neutral public library. The common runtime and portable strata do not import those hosts or concrete providers. Keep such host dependencies explicit instead of claiming a reusable platform API before a second consumer exists.

Use lower-case portable paths and short descriptive `snake_case` basenames. A folder says who owns the file; its basename says what the file does. Add a domain qualifier when a header crosses sibling modules or would otherwise collide (`tui_model`, `shell_model`); a unique, clear module concept such as `snapshot`, `extent` or `policy` need not repeat every parent directory. Do not add `disked_` to every private filename or introduce generic `common/`, `misc/` and `utils/` dumping grounds.

For each paired row below, `.h` declares the private types/ports/functions and `.c` or `.cpp` implements them. Both files are listed and linked in the map. Standalone files have their specific role stated. C versus C++ follows the selected build/target profile; a `.h` is not automatically a public SDK header. Public admitted C headers belong in root `include/`, with SDK consumers in `sdk/`.

Current file names describe implemented responsibility; they do not reserve every future class or helper. `tools/check-source-map.py` checks that every current source file is listed exactly once. Add/change the explanation when a source file is added or moved.

## Compatibility and the limits of planning

Command identities/spellings, admitted schemas/protocols, requirements, target profiles and public ABI contracts carry compatibility obligations. Private source paths, private C++ classes and helper functions do not establish those public contracts. Build recipes and source references still need updating when a private file moves.

This change maps `tui/model.*` to `tui/tui_model.*`, `gui/win32/gui_model.*` to `gui/gui_model.*`, and the former all-mode `cli.*` host to `app.*`; human CLI formatting now lives in `cli/cli.*`. Historical artifact input IDs retain their lookup identity in `spec/catalog/input-dependencies.json`, whose `path` points to the current file. Old checkout-bound evidence and scripts keep their original paths and hashes; they continue to describe the revision actually tested. There are no forwarding duplicate implementation/header files.

The architecture can fix ownership, allowed dependency direction and naming rules now. It cannot truthfully name every future file or guarantee no later decomposition. A new format, host ABI or safety result can expose a necessary split. Make those changes small, traced and tested; preserving a misleading name merely to avoid any refactor would work against stable ownership.
