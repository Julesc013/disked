# NTFS directory-name correspondence

DE-W095's [private execution contract](../spec/catalog/ntfs-membership-prototype.json)
binds directory entries and target filename instances to one supplied source,
window, profile and capture epoch. The working native probe passes193 independent cases and the three existing
supplied-reader bootstrap/closure/directory groups. Clean full-current
qualification and implementing-agent review remain pending.

The existing capture owner retains reads, target FILE/list closure, overlap
checks and final exact rereads. The membership collector compares full parent
references, original UTF16LE name bytes and namespace codes, preserving separate
instances and opaque source values. Exact correspondence does not establish
collation, lookup, uniqueness, full namespace/tree health or source authority.

Existing bootstrap/directory behavior and native/public command forms remain
unchanged. Native file/worker/public admission, content, all original 0.1.0
platform/storage requirements and owner/release gates remain separate work.

The comparison uses exact full parent references, namespace bytes and original
UTF16LE names. Each comparison row has the original one-based `header_number`
and a zero-based `target_index` into the first-encounter target inventory array.
Distinct identical filename instances contribute separately to the matching
count. Missing exact matches finish comparisons and source rereads; invalid,
stale, unsupported, changed or quota-limited input leaves an incomplete prefix.

The working evidence retains a fixture failure: a nondefault directory was
placed without an explicit directory reference. The fixture now requests its
authored identity; no product requirement or expected refusal was weakened.
